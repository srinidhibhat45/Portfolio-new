How it is put together

Plain files in version control, read into one graph in memory

Stored

Family records

One JSON file per family, kept in git. Every change has an author, a date and a reason.

Reference lists

Gotras, family deities, mathas, places, communities, surname origins, temple photos with licences.

Queue and photographs

Netlify Blobs, chosen from the environment. A laptop uses local folders.

→

When the site starts

The whole archive in memory

People, the couples derived from them, family lines, generations and counts. Every question is a walk through this graph.

Search index

Each name stored twice: as written and as its folded spelling key.

Data check

Runs before every build. Errors stop the build.

→

Served

Pages built ahead of time

Every person page and every directory page is plain HTML.

Tree viewer

The layout code runs in the browser too, so re-centring on a person needs no trip to the server.

Open JSON endpoints

Suggestions, a whole family line, a relationship, likely matches, and sending a submission.

The way back in: a maintainer's approval is committed to the repository on GitHub, and the push rebuilds the site. Without that, writes on a serverless host would vanish on the next cold start.
