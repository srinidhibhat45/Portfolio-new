How a room works

The host's browser is the game server

Host player

Host's browser tab

Makes the room code. Holds the room in memory: players, scores, the word or question, the timer.

Checks every move against the rules, then sends the whole room to everyone.

The host plays too

Its own moves go straight to the rules, with no network in between.

⇄direct link
(WebRTC)

Other players

Player's browser

Sends moves: a key, an answer, a line, a vote.

Player's browser

Draws the screen from the room it receives.

…up to the whole group

Each one joins with the code while the room is still in its lobby.

Only to get connected

Introduction service

The PeerJS broker. It finds the host by its code. No game data passes through it.

Address and relay servers

STUN tells a browser its public address. TURN relays traffic when a firewall blocks a direct link.

One server function

Hands out short-lived TURN passwords, so the account secret never ships to the browser.

If the host closes the tab, the room ends. There is no hand-over to another player and no saved state.
