How it is put together

Replays go straight from the browser. Live timing needs a small relay.

Live

F1 live-timing feed

A live socket behind a load balancer that ties each connection to a cookie.

→

In between

A request queue in the page

One request every 380 ms, to stay under OpenF1's limit of 3 a second, with retries. Data is fetched in 30-second slices around the playhead, so a full race never downloads at once.

A relay on a server

A web page cannot carry that cookie, so a server opens the socket and passes each update on as a stream the page can read. It also serves session status and the circuit outline. It runs in the local dev server or as a Netlify Function.

→

In the browser

One store

Every feed kept in time order, so any panel can ask "what was true at this moment".

Lap model

Places each car on the circuit in race mode.

Drawing

React and TypeScript. Canvas for the map and speed trace, SVG for the charts. No chart library.
