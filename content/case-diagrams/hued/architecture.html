How it is put together

The phone does the work that costs money; the server keeps the record

On the phone (Expo, React Native)

Daily colour

Worked out from the date. No server call.

Scoring and compression

The 64 × 64 copy is scored; the 1,080-pixel WebP is what gets uploaded.

Demo mode

With no server keys, the whole app runs on built-in sample data.

↔

On the server (Supabase)

Postgres

Posts (one per person per day), follows, groups, messages, notifications.

Rules in the database

Row-level security decides who reads what. Triggers keep streaks, vote and comment counts, and block users from editing their own badges or streak.

Sign-in, photo storage, two functions

Accounts, a photos bucket, push notifications and account deletion.

↔

Around it

Admin panel

A separate web app with a dashboard, analytics and moderation. Admins sign in as themselves and the database checks they are admins.

Releases

Tagging a version builds the Android APK. Every push to main sends an over-the-air update to installed apps.

Built to run on free tiers: no per-photo server work, and uploads small enough for a 1 GB storage bucket to hold thousands of photos.
