The registration workflow

From the form to the desk, one record all the way

Participant

1Event page

Opens the event. On a phone, a Register button stays at the bottom and opens the form as a sheet.

→

2The form

Name and phone always. Email, age, gender, address and custom questions only if the event asks. A UPI box if there is a fee.

→

3Checks on the server

  • Registration open, deadline not passed (Goa time)
  • Phone not already used, unless the event allows several entries
  • Places left, required answers present
  • Files checked before anything is stored
→

4Reference

YUVA-E12-00047

Event 12, entry 47. Made from the database's own row number, so it is never reused.

↓

Committee

5Registrants list

Every answer gets its own column. Payment is marked pending, paid or waived. A tick marks the entry verified.

→

6Desk sheet

Names A to Z with phone, a Present column and room to sign. Blank numbered rows for people who walk in.

7Excel export

The full list, every page of it, for anyone who needs it offline.

8After the event

The event's ledger, certificates and a drafted report draw on the same event.

If the committee allows it for an event, a participant can come back with the same phone number and correct their own entry (step 2 again, minus the phone).
