A designer's portfolio site, worked out in four pages.

Steve Wilson is a made-up designer. I used him to design a portfolio site concept: a home page, a list of work, a project page and a contact form.

In short

  • The problem: a designer's site has three jobs. Say who the designer is, show a few projects, and make it easy to get in touch.
  • What I did: I set myself that brief and designed four desktop pages around a made-up designer called Steve Wilson.
  • The key idea: keep choosing and reading apart. The work page is a short numbered list. Each project then gets one long page built from the same template.
  • Where it stands: a visual concept. There was no research and no testing, and it was never built. The name, the client and the numbers in the mock-ups are sample text, not my record.

01 The brief

I set the brief myself: who, what, how to reach me

Nobody asked for this site. I wanted to practise designing a portfolio, so I wrote the brief myself. A visitor should learn who the designer is, see a few projects and find a way to get in touch, in that order.

I did no research for it and tested it with no one. I invented a designer, Steve Wilson, so the pages had a name and some content to hold. So this page is about the design itself: how the pages are arranged, and the type and colour choices.

What is not real. Steve Wilson does not exist. His projects, the client named on the project page and the result figures are filler I typed to test the layout. None of it is my client history or my results.

02 Home page

The name is the loudest thing on the site

The home page opens with a small greeting and then the name, set 250 pixels tall. Nothing else on the site is bigger than 75. I wanted a visitor to know whose site this is before reading a sentence.

Under the name come a short About me paragraph and four services: graphic design, content writing, presentation design and logo design.

The trade-off: a huge name says nothing about why this designer is worth hiring. If I did it again, I would put one clear line about the work next to it.

03 Type, colour, layout

Eight type sizes, three colours and a few fixed widths

I measured the artwork to see what system it really uses. There are eight type sizes across the four pages. Section headings are 75 pixels, body text is 35 and the menu is 30.

The colour is just as narrow. Every page is black, with white text and one yellow. On the home page black covers 75% of the area and yellow less than 5%. Because yellow is rare, it works as a pointer: it marks the name, the page you are on and the button to press.

The layout has no strict grid, meaning a fixed set of columns that everything lines up to. It leans on repeated sizes and on centring instead.

Measuring also showed two loose ends. Headings start between 130 and 167 pixels from the left edge, depending on the page. And the project names in the work list are set in a second, plainer typeface. I would fix both.

04 Work page

The work page is a list you can scan in seconds

The work page shows four projects and nothing else. Each row has a large outline number, a colour tile, the project name, the kind of work and the tool used. There are no descriptions to read. This page is for choosing.

The four projects are sample entries. Three of them use well-known product names and logos as stand-ins. None of them is client work.

The trade-off: a list this bare depends on its labels. A project name that nobody knows would need a line saying what it is.

05 Project page

Every project gets the same long page

Choosing a project opens the long page. It is a template, which means the same fourteen blocks in the same order for every project. A reviewer who has read one knows where to look in the next.

That order is the main decision on this page. A reviewer in a hurry gets the answer before the method.

The weakness is plain in the pictures: the template is empty. It is scaffolding, and it proves nothing until a real project fills it.

06 Contact page

Three fields and one button

The contact page is the shortest, a single screen. It has fields for name, email and message, and a yellow Send button. It is the only page where white takes up real space, about 18% of it, because the fields are white.

07 What comes next

What it would need to become a real site

What exists is four flat pictures of a desktop site. To take it further, I would do these things in order.

  1. Fill the template with one real projectThen ask a reviewer to find the role, the main decision and the outcome in a quick scan.
  2. Design it for a phoneEvery page here is drawn at one desktop width.
  3. Check it can be used by everyoneContrast, keyboard use and reading order, before any build.
  4. Tidy the systemOne typeface, one left edge and darker hint text in the form.

What I took from it: a layout can earn a visitor's attention, but only real work earns their trust. I would keep the split between a list for choosing and a page for reading, and write the project pages around real decisions.
