The Office GamesDesigned and built · 12 min read

Three party games where one player's browser is the game server.

The Office Games is a small web site of three quick multiplayer games that I designed and built on my own. One player opens a room, shares a six-character code, and their browser runs the game for everyone.

In short

  • The problem: a quick group game in the browser still needs a place where the game runs and everyone can reach it. My first version needed a Node server and a host for it.
  • What I built: a hub of three games, Keyboard Scramble, Collision and The Forger. The host player's browser holds the room and checks the rules. Other browsers connect to it directly.
  • The key idea: keep the server out of the game. The only server code left hands out passwords for a relay that helps browsers behind firewalls connect.
  • Where it stands: live since July 2026, built in 34 commits over eight days. An earlier one-game prototype with the same name, Game of Lies, is a separate product and is not the live site.

01 What it is

Three short games behind one room code

The Office Games is a home page with three games on it. Each one is short and needs no account. The home page invites you to "choose a game to play with your friends".

  • Keyboard Scramble: type the word on screen while every key on your keyboard types a different letter.
  • Collision: two teams answer prompts like "Name a big cat". If too many people on a team give the same answer, the team takes a strike.
  • The Forger: everyone draws a secret word one line at a time, except the Forger, who only knows the category.

Every game starts the same way. You type a name and create a private room. You share the room code, and the others type it in to join.

How these screens were made. I captured every game screen on this page from the built site on one computer, with several browser tabs as players. The network link between players was replaced by a local stand-in, so the screens are the real interface but not a real game across devices.

02 Two products

The name was used twice, and the live link is the second product

There are two separate code bases called The Office Games. They share a name and a wordmark. They share no code.

The first, in June 2026, was one game called Game of Lies. Its rooms only work across tabs of one browser, unless each player sets up a database connection by hand. It has no hosting set up.

The second started in July 2026 as Keyboard Scramble on its own. The same morning I turned it into a hub for several games and gave it the old name. That hub is the live site, and most of this page is about it. Game of Lies has its own section near the end.

03 How a room works

One player's browser runs the game for everyone

There is no game server. Whoever creates the room becomes the host. Their browser tab holds the room in memory and checks every move against the rules. Then it sends the whole room to every player, and each screen redraws from it.

The browsers talk to each other directly through WebRTC, a browser feature for direct connections. To find each other, they use PeerJS's public introduction service. The room code is part of the host's address there, so typing the code is how you find the host.

Some networks block direct links. For those, a relay called a TURN server passes the traffic along. The relay needs a password, and a password in the page would be public. So one small server function asks the relay provider for a short-lived password and passes it on.

The trade-off. With no server, the room lives only in the host's tab. If the host closes it, the room ends, and there is no hand-over to another player. And because the whole room goes to every browser, hidden things like the Forger's secret word can be read by anyone who opens the browser's developer tools. I accepted that for a game among friends. It is not cheat-proof.

04 Decision 1

Everyone fights the same scrambled keyboard

What you see: a word to type and a picture of a keyboard. Every key types the wrong letter. As the clock runs down, a few keys at a time flip to show what they really type.

In the build: at the start of each round the host shuffles 47 keys into a new order and picks the order the hints will appear in. It sends both to every player once. Each browser then translates your key presses itself, so a round needs no messages until you finish or make a mistake.

A finished word scores 100 points, plus 10 for each second left, minus 5 for each mistake, and never less than 10. The host can change the mode (words, phrases, sentences, or a chaos mode that reverses the word), the difficulty, rounds, time and hints.

The trade-off. There is no backspace. A wrong key just counts as a mistake. And the time left is reported by each player's own browser, which the host trusts.

05 Decision 2

In Collision, matching meaning counts, not matching spelling

What you see: two teams. Each round one team gets a prompt and 30 seconds. Every member answers alone. If half the team or more give the same answer, the team takes a strike. Three strikes and that team loses.

In the build: the first rule compared answers letter for letter, ignoring only capitals and outer spaces, and a strike needed more than half the team. So "NY" and "New York" did not match, and a made-up word was accepted. On 17 July I rebuilt it, and changed the strike to half the team or more. Each question now carries its own list of accepted answers and nicknames, and each answer is matched before it counts.

The question bank went the same way. On 10 July it grew past 500 questions. I then cut it back to 44 hand-picked prompts, each with a list of answers that can be checked.

The trade-off. A checked list cuts both ways. An answer that is right but missing from my list is rejected too. And six of the 44 questions list fewer than 8 answers, so the question picker never chooses them.

06 Decision 3

In The Forger, one secret is shown to everyone but one player

What you see: the same screen, with one line different. Artists see the secret word. The Forger sees only the category and is told to blend in. Each player draws one unbroken line per turn, twice around the table.

In the build: a line is a list of points on a 600 by 400 canvas. It is sent when you lift the pen, and the host only accepts it from the player whose turn it is. That rule is what keeps "one line per turn" honest.

After everyone has drawn twice, everyone votes. A tie, or the wrong person accused, and the Forger wins. If the Forger is caught, they get one guess at the word to steal the win.

The trade-off. It needs at least three players. And as with the other games, the secret word and the Forger's identity travel to every browser. Only the screen hides them.

07 The build

The games came quickly, and the connections took the work

I started with a Node server and prepared it for two hosts, Render and Hugging Face Spaces. Before the morning was out I rewrote it so the host's browser runs the game, and deleted the server. Much of the history after that is about getting browsers to connect.

The hardest problems were the ones I could not see on one computer.

ProblemWhat went wrong, and what I changed
JoiningA player could try to connect before their own connection was ready. A short wait before connecting fixed the race. Old connections left open when you went back were also closed.
ErrorsA timeout message was replacing the real reason a join failed. Now the real error is kept.
FirewallsThe free public relay I used stopped working, so joins timed out behind firewalls. I replaced it with the password function.
The fix's fixThe function's reply had the wrong shape for the browser, and browsers then kept the bad reply in their cache. Two more commits fixed both.

There are no automated tests. One script plays ten made-up players through the Collision rules without a network. It dates from the first day and has not been updated since the answer checks arrived.

08 The first attempt

Game of Lies came first, with a demo mode that never leaves one browser

Game of Lies is the June 2026 product. Two teams, Team Stapler and Team Paperclip, take turns with office trivia. One player answers for the team and may lie. The other team's decider sees only that an answer is locked in, and chooses to steal it or pass.

The other teamAnswer was rightAnswer was a lie
PassesAnswering team +1Nobody scores
StealsStealing team +2Stealing team −2

It has two ways to share a room. In "Local Storage Sync" the room is saved in the browser, and other tabs of that same browser see each change. To play on separate devices, each player has to paste the settings of a Firebase database into the game first.

To try a round alone, the host can add up to nine simulated players. On its turn, a simulated player waits four seconds. Then it answers correctly 70% of the time, or, as the decider, steals half the time.

What the demo mode does not show. Local mode is not network play between devices. It only links tabs of one browser on one computer. The screens above were made that way. I have no record that the Firebase mode was ever used for a real game, and the project has no hosting set up.

09 Where it stands

Live, with no usage numbers and a short list of known problems

The hub is live at the link above. The last commit was on 17 July 2026. I have no player counts or notes from real sessions to report.

These problems are known and still open:

  • When the host leaves, the room ends for everyone. Other players are not told why.
  • Keyboard Scramble's results heading says "Final results!" after every round, because the screen checks a copy of the round number that is not updated during play.
  • The Forger's header reads "Round 3 / 2" while people vote.
  • The Collision card on the home page still describes the old rule: more than half, and the exact same answer.
  • Hidden information reaches every browser, and the ten-player script is out of date.

10 What I learned

Test the connection before the game

Collision and The Forger were each added within hours on 10 July. Connections took 15 of the 34 commits, and the worst failures, like a relay that quietly stopped working, could not be seen from one computer. The lesson I take from it: try joining from two different networks early, before adding the next game.

Collision taught me that a fair rule has to be one the host can check. "The same answer" sounded clear until "NY" and "New York" disagreed. Writing down the accepted answers made the rule real, and it also showed me where my lists were too short.
