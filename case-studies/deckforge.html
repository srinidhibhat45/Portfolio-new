A flat PDF deck, rebuilt as layers you can edit and animate.

DeckForge is a web app I designed and built on my own that takes a PDF of a slide deck apart into text, shapes and images you can edit, animate and present, without uploading the file.

01 Why I built it

A PDF keeps the look of a slide and loses its parts

Slides often reach you only as a PDF, exported from Keynote, PowerPoint, Google Slides, Figma, InDesign or Canva. The PDF looks right. But you cannot fix one line of text, move a logo or animate one chart.

Most "PDF to slides" tools give you a picture of each page. A PDF is really a list of drawing instructions: put these letters here, fill this shape, paint this image. The objects a person sees, such as a title or a chart, are not stored anywhere.

DeckForge takes the page apart instead. Text comes back as paragraphs, a logo as one object, and a bar chart as one series. It all happens inside the browser tab. The file is not uploaded and there is no account.

What I do not have. I designed for a presenter who has to revise a deck someone else exported. That is my own assumption. I have no interviews, user feedback or usage data, so this page does not quote any.

02 How it works

Drop a PDF, get layers back, then present or export

There are three steps. Drop in the PDF. Each page comes back as a slide of layers you can move, restyle and animate. Then present it full screen, with a phone as the remote, or export it.

Each import gets its own link and is saved in the browser on that machine. Importing a second PDF never overwrites the first.

To make the screens on this page I wrote a six-page test deck with sample text and made-up numbers, saved it as a PDF and opened it in DeckForge.

03 Layers you recognise

Layers that match what you see, not loose fragments

What you see: each layer has a name and a role, such as title, heading, body, label, shape or photo. A photo comes out as a photo. A chart comes out as one chart.

In the build: pdf.js opens the file in the browser. My code then reads each page three ways and merges the results. The first reading replays the drawing instructions one by one, keeping track of position, clipping, colour and transparency. That is what tells you where each mark really landed and in what colour.

Grouping turns hundreds of marks into a few objects. Nearby paths join into one object, so a logo made of 40 paths is one layer. Shapes that are alike and evenly spaced join into one series, so a bar chart moves as one chart.

The trade-off. Grouping and roles are a best guess from size, position and spacing. On my test file the three cards and their coloured dots came back as one shape layer. I kept the guessing visible, so a wrong name is easy to spot.

04 The honest fallback

A page that cannot be rebuilt stays a picture, and says so

What you see: on my test file, five of the six pages came back as layers. The cover did not. Its analysis failed, the import listed that in a note, and the slide kept the original page as one image. The layer panel says so in plain words.

In the build: there are three ways a page ends up as a picture. Each one keeps the page usable, and each one is reported.

What I ruled out. Forcing every page into shapes. A scanned page has no text to recover, and a dense map can hold thousands of paths. Both would come back mangled. A sharp picture is less useful than layers, but it is never wrong.

05 Auto-animate

One button animates the deck, after reading each slide

What you see: press Auto-animate and a panel works through the deck slide by slide. It says what kind of slide it found and what it will do. At the end it sums up.

In the build: each slide is checked against five questions before anything moves. The answers set the order and timing of every layer. The gap between two slides gets a transition chosen from what changes between them.

Underneath, each of the 40 animation presets is a small formula that turns progress from 0 to 1 into a position, size, blur or opacity. An exit is the same formula played backwards, so every preset works both ways.

The trade-off. There is no randomness, so the same deck animated twice makes the same choices. That makes the result easy to trust and to undo, but it never offers a second take. For a different feel, six house styles can be applied by hand.

06 The speaker sets the pace

Bullets wait for the speaker, recordings do not

What you see: any animation can start "On click" instead of with the slide. A text layer can go further and spend one press per line, so a list arrives as you talk through it.

In the build: each animation can carry a build step. Only a live talk waits for a press. Everywhere else nobody is there to press, so the editor, the thumbnails, the video export and the web export play the steps one after another.

The trade-off. The same slide now behaves two ways. If that were hidden, a speaker could export a video expecting pauses that are not there. So the panel states the rule in one sentence, right under the press picker.

07 Presenting and the remote

Two windows for the talk, and a phone as the remote

Press A while presenting and DeckForge opens an audience window with only the slides in it. You drag it to the projector, or pick it when a video call asks which window to share. The main window becomes the presenter console: the current slide, the next one, your notes and the clock.

A phone becomes the remote by scanning a QR code. It shows a live view of the slide, your notes, a laser pointer you steer with a finger, and buttons for effects such as confetti and applause.

Pairing is the one part that needs a server, because two devices cannot find each other on their own. The copy I ran for these screens was served as plain files, with nothing to pair through. Both the laptop panel and the phone say exactly that, instead of spinning forever. So I could not capture a paired phone for this page.

Those numbers came from one change. The phone's view used to wait for a timer, and browsers slow timers to once a second in a background tab. Now it repaints the moment the slide changes.

What is not local. The deck itself never leaves the browser. On the live site a small function acts as a mailbox: the phone and laptop swap a handshake through it, then talk directly. If a network blocks that, the mailbox carries slide control and small preview pictures, and keeps them for under a minute.

08 Getting it out

Three ways out: a video, one web page, or the project

A video can be up to 4K at 24, 30 or 60 frames a second, as MP4 or WebM. You can also record the talk itself in present mode: your voice over the slides, at your own pace, with the pointer and effects.

The web export is one HTML file with every animation baked into CSS, the browser's own styling language, and no JavaScript at all. Because each preset is a formula of progress, it can be sampled into CSS steps, so springy and bouncing curves survive.

The trade-off. An export with no JavaScript cannot do everything. Magic Move, where shared layers glide to their new places, falls back to a crossfade. A video clip on a slide starts when the browser is ready, not at its set point in the build.

09 The build

One renderer, one store, and the browser does the work

Everything that touches the deck runs in the browser tab. One renderer draws the canvas, the slide list, the layer thumbnails and present mode, so what you edit is what you present.

The hardest problems were small details with large effects.

AreaWhat went wrong, and what I changed
Colourpdf.js hands colours over as numbers from 0 to 255, not fractions from 0 to 1. Read the wrong way, a whole document turns white.
Thin linesA drawn horizontal line has zero height, so every underline and divider vanished. The stroke width now pads the line's box.
FontsFonts inside the PDF are lifted out and installed in the browser, then checked against the widths the PDF recorded. A font that fails the check is swapped for a substitute instead of printing blanks.

RecordingThe recording clock runs in a separate worker, so it keeps going when the audience window covers the editor.

10 Contrast and keyboard

Contrast is a test the build must pass, not a promise

Every colour in the interface comes from one set of named values, so one change themes the whole app in light and dark. Text and controls are held to WCAG 2.1 AA, the common accessibility standard. A contrast ratio says how far apart two colours are in brightness; body text needs at least 4.5 to 1, and the edge of a control needs 3 to 1.

A test reads the real stylesheet and fails if any pairing the app uses drops below its floor. The interface also works from the keyboard, with a visible focus ring, dialogs that hold and return focus, targets at least 24 pixels across, and reduced motion respected.

What this does not prove. These are checks on colour and code. They are not an accessibility audit, and I do not claim one.

11 Where it stands

Live and free, with no usage numbers yet

DeckForge is live at deckforge.srinidhibhat.com, version 0.1.0, under the MIT licence. It is free and asks for no sign-up.

I have no user counts, feedback or measured success rate for extraction, and no results from a set of real-world decks. These limits are known:

  • Gradients come back as flat colour.
  • Scanned pages have no text to recover; they stay pictures.
  • Very dense artwork, such as maps, stays a picture instead of shapes.
  • Rotated text is handled line by line, not as a paragraph.
  • Magic Move does not carry into the web export, where it becomes a crossfade.
  • Direct pairing carries one phone. A second phone falls back to the mailbox.
  • Video and GIFs travel inside the project file, up to 48 MB each.

The screens on this page come from a built copy on my machine and my own test file, so details may differ slightly from the live site.

12 What is next

Test it on hard decks, then widen what it can export

  • Find out why the cover of my test file failed to rebuild.
  • Proposed: import a fixed set of decks, including clean text, scanned, multi-column and dense vector pages, and record how editable and how faithful each one is, separately.
  • Planned and not built: Magic Move in the web export, motion paths, a relay server so direct pairing works across networks, trimming a recording inside the app, editing with others at the same time, and ready-animated slide templates.

13 What I learned

A guess is fine when it shows that it is a guess

Taking a PDF apart is guesswork. The PDF never says "this is a title" or "these six bars are a chart". What made the guesses useful was showing them: a named role on every layer, a note when a page fails, a panel that says nothing can be edited here.

The same rule held outside extraction. The pairing panel names the missing service instead of spinning. The animation panel says which places wait for a press. And a clean six-page test file of my own still turned up a failed cover, a lost word gap and a wrong role. Next time I would start with the hardest decks I can find.
